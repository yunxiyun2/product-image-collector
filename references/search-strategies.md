# 搜索策略

## 共通规则

先按原始名检索，再用标准名和输入简介中的实际关键词补搜。可使用公司消歧，失败后去掉公司限制。查询来自真实执行，不编造历史。预置域名只是线索，始终允许通用搜索发现新网站。

不要多个产品OR查询后宣布逐个检索完成，不把HTTP200空壳当无结果。优先产品专属详情页，来源失效换独立站点。标准名、搜索摘要、同公司和同名都不是充分身份关系证据。

## 游戏

顺序：产品名 游戏 → 精确名 游戏 下载 → 名称 介绍/攻略/小程序 + 已有描述线索。优先目标轮播，后备目标明确的介绍、攻略、宣传图。可参考游戏模板种子，但不只搜索这些站。

同名不同语义版本、攻略引用其他游戏和相关推荐不能混收。小游戏无App Store覆盖时继续游戏介绍、小程序和下载站路线，不反复盲查iTunes。

## App

顺序：产品名 应用宝 → 精确名 app 下载 → 官网、App Store、下载站、介绍和教程。应用宝搜索/预约页推荐图不是目标轮播；App Store截图需来自同trackId的可确认字段，iOS与Android分开记录。

保留功能界面、教程和宣传类型差异。不同包名或版本来源不自动证明同一个安装包，不采APK。

## 商品

顺序：品牌 核心品名 官网 → 精确品名 商品详情/图片 → 独立商品来源。简介中的容量、色号、型号帮助判定，但不得编造规格。

目标SKU不明确时不自动选其他SKU。电商登录/频控则换官网或其他公开来源，不等待解锁。记录product_image，不叫App截图。

## 品牌

顺序：品牌 官网 → 品牌介绍/产品目录 → 明确品牌来源。允许品牌主视觉和确属该品牌的目录商品图，逐图记录brand_image或product_image，以及可见sku_name。

只命中同名商品不意味着确认品牌。具体商品图不冒充品牌全貌，不将商品选择解释为用户指定SKU。

## 服务、小程序和短剧

顺序：精确名 小程序/官网/服务介绍 → 输入中的描述关键词和公司线索。取对应服务页或目标剧目素材，标service_page/promotional_image。

宿主App、泛行业插画、其他剧海报不能代替目标。公司另一个产品只作线索。输入泛化且来源仍无法消歧时返回ambiguous_target。
